# RCA 리포트 마스킹 규칙

리포트를 저장하기 전에 본문 · 표 · 원문 발췌 · 명령 예시 전체에 적용한다.

| 항목 | 규칙 | 예 |
|---|---|---|
| IP 주소 | 앞 두 옥텟만 남기고 뒤 두 옥텟을 `x.x` 로 바꾼다 | `10.20.x.x` |
| 구분이 필요한 IP | 호스트 · 단말을 구별해야 분석이 읽히면 역할 별칭으로 바꾼다. 같은 대상은 문서 전체에서 같은 별칭을 쓴다 | `API-1`, `API-2`, `교사단말A`, `교사단말B` |
| 이메일 | 로컬 부분을 `***` 로 바꾸고 도메인만 남긴다 | `***@example.com` |
| 학생 식별자(`STU-…`) | 등장 순서대로 별칭을 붙인다. 같은 학생은 문서 전체에서 같은 별칭을 쓴다 | `학생A`, `학생B` |
| 토큰 · API 키 | 키 이름은 남기고 값 전체를 `***` 로 바꾼다. 앞뒤 일부도 남기지 않는다 | `token=***` |
| 비밀번호 · 접속 문자열 | 비밀번호와 계정 정보를 `***` 로 바꾼다. 드라이버 · 호스트 역할 · 포트처럼 분석에 필요한 부분만 남긴다 | `jdbc:mariadb://***:3306/itembank?user=***&password=***` |

## 적용 방법

- 별칭 대응은 작성하는 동안 머릿속(대화 안)에서만 유지한다. 대응표를 파일 · 임시 폴더에 남기지 않는다.
- 저장 직전에 리포트 파일을 `grep -nE` 로 다시 훑어 IP · 이메일 · `STU-` · `token` · `password` 패턴이 남아 있지 않은지 확인한다.
- 문서 끝에 적용 건수를 한 줄로 적는다.
  예: `마스킹 적용: IP 2건(10.20.x.x · 역할 별칭 API-2) · 이메일 1건 · 학생 식별자 4건(별칭 2명) · 토큰 0건 · 비밀번호 · 접속 문자열 1건`
