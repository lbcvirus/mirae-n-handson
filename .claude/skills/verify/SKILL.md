# 머지 전 검증

검증 대상: $ARGUMENTS

- 인자가 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 인자가 `.patch` 파일이면 적용하지 않고 `git apply --stat <파일>` 과 파일 내용으로 읽는다.
- 절차는 저장소 루트의 `templates/verification-loop.md` 를, 판정 항목과 심각도 정의는 저장소 루트의 `templates/approval-checklist.md` 를 따른다. 체크리스트 항목은 여기 옮겨 적지 않고 매번 그 파일을 읽는다.

## 1. 요청 범위 확인

1. 이 변경으로 무엇을 요청했는지 한 문장으로 확인한다.
2. 요청 문장이 대화에 없으면 **판정하지 말고** 먼저 사람에게 묻고 멈춘다.

## 2. 변경 파일 목록과 diff 읽기

1. `git diff --stat <대상>` (patch 면 `git apply --stat <파일>`) 으로 변경 파일 목록을 먼저 뽑는다.
2. 파일마다 diff 를 읽는다. 판단에 앞뒤 문맥이 필요하면 해당 파일을 `Read` 로 연다.

## 3. 체크리스트 대조

1. 저장소 루트의 `templates/approval-checklist.md` 를 읽는다.
2. 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
3. 컨벤션 기준은 팀 `CLAUDE.md` 와 대조한다. `convention-check` Skill 이 있으면 그 결과를 쓴다.

## 4. 테스트 실행

변경된 폴더의 테스트만 실행한다.

| 변경된 폴더 | 명령 |
|---|---|
| `modern/api` | `cd modern/api && ./gradlew test` |
| `modern/web` | `cd modern/web && npm test` |
| 이관 코드(레거시 규칙을 옮긴 `modern/api`) | `cd characterization && npm test` (레거시 대상) 와 `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 출력은 통과 · 실패 수와 실패한 테스트 이름만 남긴다. 전체 로그를 대화에 싣지 않는다(예: `tail`, `grep` 으로 요약 줄만 본다).
- characterization 이 실패하면 실패한 케이스 이름과 스냅샷 차이를 그대로 적는다.
- 서버가 꺼져 있거나 의존성이 설치되지 않아 실행할 수 없으면 그 사실을 적고 사람에게 기동을 요청한다. 이 경우 "테스트 통과"는 미충족이다.

## 5. 승인 기준 판정

- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다. 하나라도 미충족이면 반려.
- 치명 · 경고 · 제안의 구분은 `templates/approval-checklist.md` 의 심각도 정의를 따른다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 본다.

## 6. 출력 형식 (순서 고정)

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|
| 1 | 치명 / 경고 / 제안 | `경로:줄` | … | … |

확인 필요
- 줄번호를 댈 수 없는 지적, 사람에게 물어야 하는 것
```

- 이슈 한 건은 심각도(치명 / 경고 / 제안) · `파일:줄번호` · 근거 · 수정 방향 네 칸을 모두 채운다.
- 이슈가 없으면 표 대신 "이슈 없음"이라고 적는다.

## 7. 하지 말 것

- 코드를 수정하지 않는다. 판정과 수정 방향만 보고한다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- patch 파일을 적용하지 않는다. `characterization/` 의 테스트 코드와 스냅샷을 고치거나 `-u` 로 다시 찍지 않는다.
