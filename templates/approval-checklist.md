# 승인 체크리스트 v1 · 2회차

오늘 바뀐 점
1. 테스트 통과: 변경된 모듈에 실행할 테스트가 하나도 없으면 통과로 본다. 새 메서드 · 엔드포인트마다 테스트 1개 이상 규칙은 유지한다.
2. 치명 이슈: SQL injection 판별 항목을 구체화했다(문자열 연결 · 포맷 · 정렬 컬럼 · LIKE). 비밀값 · 데이터 삭제 항목은 그대로 둔다.
3. 범위 · 컨벤션: 범위 이탈 항목을 보편 기준으로 늘리고, 출력문 · 예외 처리 · 메모리 누수 항목을 추가했다. 모든 항목을 예/아니오 문장으로 바꿨다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.
항목은 모두 예/아니오로 답한다. 각 기준의 항목이 전부 "예"면 그 기준은 충족이다(괄호 안 조건에 해당하지 않는 항목은 "예"로 본다).

## 심각도 정의

- **치명** — 그대로 머지하면 서비스나 데이터에 피해를 줄 수 있는 문제. 2절 항목 중 하나라도 "아니오"면 치명이다. 1건이라도 있으면 반려.
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 1 · 3 · 4절 항목의 "아니오"는 경고 이상이며 그 기준을 미충족으로 만든다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] (변경된 모듈에 실행할 테스트가 하나도 없으면) 그 사실을 근거 칸에 "테스트 없음 — 통과로 봄"으로 적었다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.
- [ ] 새 public 서비스 메서드와 새 엔드포인트마다 그것을 호출하는 테스트가 1개 이상 있다.

## 2. 치명 이슈 0건

- [ ] SQL · JPQL 문자열에 외부 입력을 `+` · `String.format` · `concat` · `StringBuilder` 로 이어 붙인 곳이 없다.
- [ ] `JdbcTemplate` · `createQuery` · `createNativeQuery` · `@Query` 에 들어가는 외부 입력이 모두 `?` 또는 `:name` 파라미터로 바인딩된다.
- [ ] (정렬 컬럼명 · 정렬 방향을 요청 값으로 받으면) 허용 목록에서 고른 값만 SQL 에 들어간다.
- [ ] (`LIKE` 검색이 있으면) 검색어가 문자열 연결이 아니라 파라미터로 전달된다.
- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다(실습용 더미 `app-pass`, `readonly-pass` 제외).
- [ ] (데이터를 지우거나 덮어쓰는 코드가 새로 생겼으면) 요청에 그 내용이 적혀 있다.

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청과 무관한 리팩토링 · 이름 변경 · 포맷팅 · import 정리가 없다.
- [ ] PR 설명 · 커밋 메시지에 "주변 정리" · "가독성 개선"처럼 요청 밖 작업을 적은 문장이 없다.
- [ ] (기존 public 메서드 시그니처 · 엔드포인트 경로 · 응답 필드를 바꾸거나 지웠으면) 요청에 적혀 있다.
- [ ] (의존성 · DB 스키마 · 설정 파일 · 빌드 스크립트 · CI 설정 변경이 있으면) 요청에 적혀 있다.
- [ ] lock 파일 · 빌드 산출물 · IDE 설정(`.idea/`, `.vscode/`)이 변경분에 섞여 있지 않다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).
- [ ] 컨트롤러에서 Repository · SQL 을 직접 호출하는 곳이 없다.
- [ ] `System.out.print` · `System.out.println` · `System.out.printf` · `System.err.*` · `printStackTrace()` · `console.log` 가 없다.
- [ ] 비어 있는 `catch` 블록이 없다.
- [ ] `GlobalExceptionHandler` 밖에서 `catch (Exception e)` · `catch (Throwable t)` 로 넓게 잡는 곳이 없다.
- [ ] 예외를 바꿔 던질 때 원인 예외(`e`)를 새 예외 생성자에 넘긴다.
- [ ] (`InterruptedException` 을 잡으면) `Thread.currentThread().interrupt()` 를 호출한다.
- [ ] 새로 연 `AutoCloseable` 자원(`InputStream` · `Connection` · `ResultSet` 등)은 모두 try-with-resources 로 닫힌다.
- [ ] `static` 컬렉션에 요청마다 값을 넣기만 하고 지우지 않는 곳이 없다.
- [ ] (`ThreadLocal` 을 쓰면) `finally` 에서 `remove()` 한다.
- [ ] `HttpClient` · `ExecutorService` 를 요청마다 새로 만들지 않는다.
- [ ] (`ExecutorService` 를 직접 만들었으면) 종료 시 `shutdown()` 한다.
- [ ] (web, `useEffect` 에서 리스너 · 타이머 · 구독을 등록하면) cleanup 함수에서 해제한다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
